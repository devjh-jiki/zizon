# Anti-Slop Frontend (안티슬롭 프론트엔드)

대부분의 AI 프론트엔드 출력이 나쁜 이유는 모델이 브리프를 읽는 대신 기본 미감으로 점프하기 때문이다. 이 스킬은 그걸 막는 규율이다: 상황을 읽고, 진짜 방향을 고르고, 기계가 만든 티가 나는 tell 을 적극적으로 피한다.

**범위:** 랜딩 페이지, 포트폴리오, 마케팅 사이트, 리디자인. 대시보드·데이터 테이블·다단계 제품 플로우는 아니다. 여기 모든 규칙은 *상황 의존적*이다 — 브리프를 읽고 맞는 것만 꺼내 써라. 자동으로 발동하는 건 없다.

> 앱 전체에 걸친 체계적·토큰 기반 디자인 시스템(base → semantic 토큰, 컴포넌트, 테마)이 필요하면 `design-system` 스킬을 써라. 이 스킬은 **마케팅 화면에서의 취향과 안티슬롭 감별**에 관한 것이다.

## 1. 무엇보다 먼저 상황을 읽어라

코드나 다이얼을 건드리기 전에, 사용자가 실제로 원하는 걸 추론하라. 읽을 신호:

1. **페이지 종류** — 랜딩(SaaS/소비자/에이전시/이벤트), 포트폴리오(개발자/디자이너/스튜디오), 리디자인(보존 vs 전면개편), 에디토리얼/블로그.
2. **바이브 단어** — "미니멀", "Linear 스타일", "Awwwards", "브루탈리즘", "프리미엄 소비자", "애플 같은", "에디토리얼", "플레이풀", "진지한 B2B".
3. **레퍼런스 신호** — 링크한 URL, 붙인 스크린샷, 언급한 제품/브랜드.
4. **오디언스** — B2B 구매 심사단 vs 디자인에 민감한 소비자 vs 포트폴리오를 스캔하는 채용담당자. 미감을 고르는 건 오디언스지 네 취향이 아니다.
5. **이미 있는 브랜드 자산** — 로고, 컬러, 타입, 사진. 리디자인에선 옵션이 아니라 출발 재료다.
6. **조용한 제약** — 접근성 우선, 공공, 규제 산업, 신뢰 우선 커머스, 아동용. 이 제약은 미감 선호를 **덮어쓴다**.

**코드 생성 전에 한 줄 "Design Read" 를 출력하라:**

> "이걸 이렇게 읽음: `<페이지 종류>` for `<오디언스>`, `<바이브>` 언어로, `<디자인 시스템 또는 미감 계열>` 지향."

브리프가 정말 모호하면 **딱 하나** 명료화 질문만 하라(예: "Linear-clean 에 가깝게 vs Awwwards-experimental 에 가깝게?"). 자신 있게 추론 가능하면 묻지 마라 — read 를 선언하고 진행.

## 2. 세 개의 다이얼

read 이후 세 다이얼(1–10)을 설정한다. 모든 레이아웃/모션/밀도 결정이 이걸로 게이팅된다. 기본 **8 / 6 / 4**; read 가 이를 덮어쓴다(추론 표와 프리셋은 `references/dials-and-systems.md`).

- **DESIGN_VARIANCE** — 1 = 완전 대칭, 10 = 예술적 카오스
- **MOTION_INTENSITY** — 1 = 정적, 10 = 시네마틱 / 피직스
- **VISUAL_DENSITY** — 1 = 아트 갤러리 / 여백, 10 = 콕핏 / 빽빽한 데이터

## 3. 진짜 시스템 vs 미감

공식 패키지가 있는 걸 CSS로 직접 발명하지 말고, 트렌드를 공식 시스템인 척하지 마라.

- **브리프가 이름 있는 시스템으로 읽힘**(Fluent, Material, Carbon, Polaris, Atlassian, Primer, GOV.UK, USWDS, Radix Themes, shadcn/ui, Tailwind)? **공식** 패키지를 설치해 써라. CSS를 손으로 재현하지 마라. 프로젝트당 하나의 시스템. `references/dials-and-systems.md` 참고.
- **브리프가 시스템이 아니라 미감**(글래스모피즘, 벤토, 브루탈리즘, 에디토리얼, 다크테크, 오로라/메시, 키네틱 타입)? 네이티브 CSS + Tailwind + 유지보수되는 라이브러리로 만들고, 주석에서 빌려온 영감 vs 공식 재료를 정직하게 밝혀라. "Apple Liquid Glass" 는 공식 웹 패키지가 **없다** — 웹 버전은 근사치라고 라벨링.

## 4. 안티-디폴트 규율 (이 스킬의 핵심)

LLM 기본값에 손을 뻗지 마라. 가장 많이 테스트된 AI tell 들이다; 브리프가 명시적으로 요청하지 않는 한 피하라:

- **AI-퍼플 / 블루 글로우** 그라디언트, 네온 버튼 후광. 중립 베이스(zinc/slate/stone) + 고대비 액센트 하나, 채도 < 80%.
- **Inter + slate-900** 자동 기본값. Geist / Outfit / Satoshi / Cabinet Grotesk 또는 브랜드에 맞는 서체 선호. (중립/Linear 스타일 요청이나 접근성 우선일 때 Inter 는 OK.)
- **"창의적이라서" 세리프** — 기본 반사로는 금지. `Fraunces`, `Instrument Serif` 는 기본값으로 특히 금지. 세리프는 브랜드가 지정했거나 계열이 진짜 에디토리얼/럭셔리/헤리티지일 때만.
- **다크 메시 위 중앙 히어로** — DESIGN_VARIANCE > 4 일 때. 스플릿 스크린, 좌-콘텐츠/우-에셋, 비대칭 여백으로 강제.
- **모든 섹션 위 eyebrow 라벨** (`text-[11px] uppercase tracking-[0.18em]`). 3섹션당 최대 1개. 프로덕션에서 가장 많이 위반되는 규칙.
- **베이지/크림 + 브라스/클레이 + 에스프레소** — 모든 프리미엄 소비자 브리프에서. 기본 선택으로 금지 — 매번 다른 팔레트 계열로 로테이션.
- **똑같은 3개 피처 카드**, div 기반 가짜 스크린샷, 모든 것에 글래스모피즘, 모든 카드에 무한 마이크로 애니메이션.

전체 tell 목록, 금지된 프리미엄-소비자 hex 계열, 팔레트 로테이션 규칙은 `references/ai-tells.md`.

## 5. 절대 타협 불가 (절대 단순화로 없애지 마라)

- **접근성:** 모든 버튼·폼 필드·플레이스홀더·포커스 링에 WCAG AA 대비. CTA 감사(흰 버튼+흰 글자, 사진 위 테두리 없는 투명 → 금지)를 배포 전에.
- **모션 감소:** MOTION_INTENSITY 3 초과 모션은 `prefers-reduced-motion` 을 존중하고 정적으로 붕괴해야 함.
- **다크 모드:** 처음부터 두 모드 설계; 페이지당 하나의 테마 고정(다크 페이지 중간에 라이트 섹션 금지). 순수 `#000`/`#fff` 금지.
- **실제 이미지:** 미니멀 사이트조차 실제 이미지가 필요. 그라디언트 블롭만 있는 텍스트 페이지는 미니멀리즘이 아니라 미완성이다. 이미지-gen 툴 있으면 사용, 없으면 실제 사진 소스, 최후엔 명확히 라벨된 플레이스홀더 슬롯 + 사용자에게 통지 — div 기반 가짜 스크린샷은 절대 금지.
- **인터랙티브 상태:** 로딩(최종 형태에 맞는 스켈레톤, 스피너 아님), 빈 상태, 에러, 촉각적 `:active` 피드백. 성공 상태만 만들지 마라.
- **모션은 동기가 있어야:** 각 애니메이션은 위계·스토리텔링·피드백·상태 변화를 전달한다. "멋있어서" 는 이유가 아니다.

## 6. 프리플라이트 체크 (완료 선언 전)

기계적 패스 — 전체 체크리스트는 `references/preflight.md`. 가치 높은 것들:

- 히어로가 초기 뷰포트에 맞음; 헤드라인 ≤ 2줄, 서브텍스트 ≤ 20단어, CTA 스크롤 없이 보임.
- 내비가 데스크톱에서 한 줄; 높이 ≤ 80px.
- eyebrow 개수 ≤ ceil(섹션수 / 3).
- 같은 레이아웃 계열을 두 섹션이 공유하지 않음; image+text 지그재그 연속 ≤ 2행.
- 페이지 전체에 액센트 컬러 하나, 코너 반경 스케일 하나, 카피 레지스터 하나.
- 카피 자가 감사: 보이는 모든 문자열 재독; 문법 깨진 것·AI 환각 귀여운 말장난·가짜로 정밀한 조작 숫자 재작성.
- 버튼 대비, 폼 대비, CTA 텍스트 한 줄, 중복 의도 CTA 금지.

## 워크플로

1. **읽기** → 한 줄 Design Read 를 진술.
2. **다이얼** → read 에서 VARIANCE / MOTION / DENSITY 설정.
3. **기반** → 공식 시스템 또는 정직한 미감 빌드(섹션 3).
4. **빌드** → 안티-디폴트 규율(섹션 4)과 절대 불가(섹션 5) 적용.
5. **프리플라이트** → 완료 선언 전 기계적 체크(섹션 6). 리디자인이면 기존 UI를 먼저 감사(`references/preflight.md`).
